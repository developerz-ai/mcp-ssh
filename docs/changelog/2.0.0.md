# 2.0.0 — 2026-11-14

A major release: the fixes from the deep-dive audit
([plan](../plans/2026/11/13/101-deep-dive-audit-fixes/overview.md), #61, #62, #63, #68). Several are
deliberate behaviour changes. Read **Upgrading** before you roll it out.

## Upgrading — what you must do

1. **Every client logs in again, once.** Tokens are now stored as SHA-256 hashes, so the
   plaintext tokens in an existing database stop working on first start. Claude and other GUI
   clients prompt for a fresh login (remove/re-add the connector if one doesn't); re-run
   `bin/mcp-token` for headless clients.
2. **The login is a page now, not a Basic-auth prompt.** `/authorize` renders mcp-ssh's own
   consent form showing where the code will be sent; the code is issued only when that form is
   submitted. Any script that drove `/authorize` with an `Authorization: Basic` header must do the
   GET-form / POST-credentials exchange instead — `bin/mcp-token` already does.
3. **Docker needs a volume and `MCP_SSH_ALLOWED_HOSTS`.** The image binds `0.0.0.0:1337` inside the
   container, so the server refuses to start without `MCP_SSH_ALLOWED_HOSTS`. Mount
   `-v mcp-ssh-state:/var/lib/mcp-ssh`, or every container recreate logs every client out and
   drops job history. See [docs/deploy.md](../deploy.md#-docker).
4. **The installer requires `SHA256SUMS`.** `deploy/install.sh` verifies the `.deb` against the
   release's `SHA256SUMS` and refuses a release without one (every release from this one on
   ships it).
5. **Restarting the service ends running jobs.** The unit now sets `KillMode=control-group`
   explicitly (and `TimeoutStopSec=20`): `systemctl restart mcp-ssh` stops every job the agent
   started. Finish or note long-running jobs before upgrading.
6. **Empty credentials refuse to start.** `MCP_SSH_USER=` / `MCP_SSH_PASS=` (empty) used to boot
   and serve; now they count as unset.

## Breaking changes for agents (tool surface)

The surface is still three tools (`bash`, `job`, `file`); what changed is strictness and safety.

- **`file(action="delete")` of a non-empty directory needs `recursive=true`.** Without it nothing
  is deleted and the error says how to opt in. A symlink is always unlinked, never followed —
  `link/` no longer empties the target directory.
- **Unknown arguments are errors.** All three tools reject fields they don't know
  (`recurse=true`, `offset=200`) instead of silently ignoring them.
- **An unknown `job` action is an error** naming `poll`, `list`, `kill`. A non-string placeholder
  (`null`, `true`) or a missing `action` still means `list`.
- **`file(action="write")` is atomic** (temp file in the same directory + rename). An existing
  file keeps its mode and a symlink is written through to its target; hard links to the old
  inode keep the old content.
- **`job(action="list")` is paged**: newest first, at most 200 per page, with
  `[older jobs: job(action="list", cursor=N)]` when more exist.
- **`job(action="poll")` cursors are byte offsets** into the log, named by the footer
  `[latest N lines shown; earlier output: job(action="poll", id="…", cursor=C)]`. Pass them back
  verbatim; don't compute them.
- **`job(action="kill")` reports what actually happened**: `killed`, leftovers killed, not
  running, survived TERM+KILL, or could-not-signal. Only the first two mean the group is gone.
- **`bash` limits**: `timeout` is clamped to 600s; a job whose output passes 256 MiB is killed and
  finishes `failed`.

## Auth and sessions

- Access tokens last 24h; refresh tokens **30 days** (were 365), rotated on use, within a
  **90-day** absolute lifetime per login. Reusing an already-rotated refresh token revokes that
  whole login.
- `mcp-ssh sessions --revoke` ends every login. `mcp-ssh set-auth` now revokes every session too.
- Registered clients are capped (1000) and swept once 7+ days old with no live token.
- `/token` and the consent page are `no-store`; a token-store outage is a `503`, not
  `invalid_grant`.

## Reliability

- Polling a huge job log no longer reads it into memory (a poll on a large live log could
  OOM the server); every log read is bounded by its page budget.
- Kills use `kill(2)` directly (the Docker image had no `kill` binary, so every kill reported
  success while signalling nothing) and succeed only once the process group is verifiably gone.
- The reaper never kills: retention is measured from when a job **finished**, and running jobs are
  never aged out.
- `file(action="read")` on a device or FIFO errors promptly instead of hanging.
- SIGTERM with open MCP streams exits within the 10s drain deadline (unit `TimeoutStopSec=20`).
- The database is created `0600` and job logs `0600`; schema changes are versioned migrations.

## Ops

- Release builds are `--locked` on a pinned toolchain (1.100.0); CI runs `cargo audit`,
  smoke-tests the amd64 and arm64 `.deb`s and images, and runs the end-to-end suite (`bin/e2e`).
- The `.deb` now creates the `mcp-ssh` user and `/etc/mcp-ssh` itself (the by-hand install used
  to fail with `217/USER`), ships for **amd64 and arm64**, and needs glibc ≥ 2.35
  (Debian 12, Ubuntu 22.04 or newer). The image runs under `tini` and has a `HEALTHCHECK`.
- The default systemd unit no longer sets `ProtectSystem` (it broke `sudo` self-management);
  the documented lockdown drop-in keeps it.
